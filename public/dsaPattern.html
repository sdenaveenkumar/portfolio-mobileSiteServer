1. The Sliding Window

What it does: It creates a "window" (a subset of elements) over a sequential data structure like an Array or String. Instead of recalculating data for every possible subset (which takes O(N2) time), the window "slides" to the right by adding the next element and removing the oldest element, reducing the time complexity to O(N).

Use case: Use this whenever a problem asks for a  contiguous subarray or substring (e.g., "longest," "shortest," or "maximum sum").

Real MNC Problems it Solves: *  Network Rate Limiting: Checking if a user has exceeded their allowed API requests within a rolling 60-second window.

  • E-Commerce Analytics: Calculating the 7-day moving average of sales revenue without recalculating the entire week's data every single day.

The Java Skeleton (Dynamic Window Size):

public int slidingWindowTemplate(int[] nums, int target) {

int windowStart = 0;

int currentSum = 0; // Or whatever metric you are tracking

int maxLength = 0;

for (int windowEnd = 0; windowEnd < nums.length; windowEnd++) {

// 1. Add the next element to the window

currentSum += nums[windowEnd];

// 2. Check if the window violates our condition

while (currentSum > target) {

// 3. Remove the element going out of the window

currentSum -= nums[windowStart];

// 4. Slide the window ahead

windowStart++;

}

// 5. Update our best result so far

maxLength = Math.max(maxLength, windowEnd - windowStart + 1);

}

return maxLength;

}

Common Variations:

Maximum Sum Subarray of Size K: (Fixed window size)

Longest Substring with K Distinct Characters: (Dynamic window using a  HashMap to track character frequency)

String Anagrams: (Fixed window using two character-count arrays)

Minimum Window Substring: (Dynamic window, often considered a "Hard" LeetCode problem, but easily solved with this exact template)

2. Two Pointers

  • What it does: It uses two integer variables as indices pointing to different elements in an Array or String. They usually start at opposite ends and move toward each other, or they move in the same direction at different intervals.
  • Use case: Use this when dealing with  sorted arrays or strings, or when you need to find a pair of elements that satisfy a specific constraint (like a target sum) in O(N) time and O(1) space.
  • Real MNC Problems it Solves:
  • Financial Transactions: Finding two past transactions in a sorted ledger that equal a specific disputed refund amount.
  • Data Validation: Verifying if a user's input string is a valid palindrome (reads the same forward and backward) before storing it in the database.

The Java Skeleton (Opposite Ends):

public int[] twoPointersTemplate(int[] arr, int targetSum) {

int left = 0;

int right = arr.length - 1;

while (left < right) {

int currentSum = arr[left] + arr[right];

if (currentSum == targetSum) {

return new int[] {left, right}; // Found the pair

}

if (currentSum < targetSum) {

left++; // Need a larger sum, move the left pointer right

} else {

right--; // Need a smaller sum, move the right pointer left

}

}

return new int[] {-1, -1}; // Pair not found

}

Common Variations:

1. Two Sum II: (Finding pairs in a sorted array)

2. Squaring a Sorted Array: (Handling negative numbers by comparing the absolute values at the  left and  rightpointers)

3. 3Sum / Triplet Sum to Zero: (Fixing one number and using Two Pointers for the remaining array)

4. Container With Most Water: (Maximizing area by moving the pointer pointing to the shorter line)

5. Remove Duplicates In-Place: (Using two pointers moving in the same direction, one to read and one to write)

3. Fast & Slow Pointers (Tortoise & Hare)

  • What it does: A specialized version of Two Pointers where two indices move through a data structure (almost always a Linked List) at different speeds. Usually, the "slow" pointer moves one step at a time, while the "fast" pointer moves two steps.
  • Use case: Use this to detect cycles (loops) in a Linked List, to find the exact middle of a Linked List without knowing its length, or to detect infinite loops in state machines.
  • Real MNC Problems it Solves:
  • Network Routing Protocols: Detecting if a data packet is caught in an infinite loop between routers (a cyclic path).
  • Memory Leak Detection: Identifying circular references in objects during garbage collection in runtime environments (like the V8 engine powering Node.js).

The Java Skeleton (Cycle Detection):

class ListNode {

int val;

ListNode next;

}

public boolean hasCycle(ListNode head) {

if (head == null || [head.next](http://head.next) == null) {

return false;

}

ListNode slow = head;

ListNode fast = head;

while (fast != null && [fast.next](http://fast.next) != null) {

slow = [slow.next](http://slow.next);         // Moves 1 step

fast = [fast.next.next](http://fast.next.next);    // Moves 2 steps

if (slow == fast) {

return true; // The fast pointer "lapped" the slow pointer; a cycle exists

}

}

return false; // Fast pointer reached the end; no cycle

}

Common Variations:

1. LinkedList Cycle Detection: (The classic template above)

2. Middle of the LinkedList: (When the fast pointer reaches the end, the slow pointer will be exactly in the middle)

3. Start of LinkedList Cycle: (Requires math: once they meet, reset one pointer to the  head and move both at 1 step per loop; where they meet again is the start of the cycle)

4. Happy Number: (Mapping a mathematical process to a Linked List to see if it loops infinitely)

5. Find the Duplicate Number: (Using Floyd's Tortoise and Hare algorithm on an array mapping)

4. Merge Intervals

  • What it does: This pattern deals with overlapping timelines or ranges. The trick is always the same:  Sort the array based on the starting time of each interval, and then compare the current interval's ending time with the next interval's starting time to see if they overlap.
  • Real MNC Problems it Solves:
  • Calendar/Scheduling Apps: Merging overlapping meetings in an Outlook or Google Calendar clone.
  • Cloud Infrastructure: Calculating the total duration of server downtimes when multiple error logs overlap.

The Java Skeleton:

import java.util.*;

public int[][] mergeIntervalsTemplate(int[][] intervals) {

if (intervals.length <= 1) return intervals;

// 1. Sort intervals strictly by their starting values

Arrays.sort(intervals, (a, b) -> [Integer.compare](http://Integer.compare)(a[0], b[0]));

List<int[]> merged = new ArrayList<>();

int[] currentInterval = intervals[0];

merged.add(currentInterval);

for (int[] nextInterval : intervals) {

// 2. If the current interval's END is >= next interval's START, they overlap

if (currentInterval[1] >= nextInterval[0]) {

// Merge them by taking the maximum end time

currentInterval[1] = Math.max(currentInterval[1], nextInterval[1]);

} else {

// No overlap, add the next interval to the list and update the current tracker

currentInterval = nextInterval;

merged.add(currentInterval);

}

}

return merged.toArray(new int[merged.size()][]);

}

Common Variations (with details):

1. Insert Interval: You are given a list of  already sorted and non-overlapping intervals, plus one new interval. You must insert the new one in the correct spot and merge any resulting overlaps.

2. Intervals Intersection: You are given two separate lists of intervals (e.g., User A's free time and User B's free time) and you need to find the exact intervals where they overlap (finding a time to meet).

3. Meeting Rooms II (Classic MNC Question): Given an array of meeting time intervals, find the  minimum number of conference rooms required. (This variation combines sorting the intervals with a Java  PriorityQueue to track when rooms become empty).

5. Cyclic Sort

  • What it does: This is a highly specific but incredibly powerful pattern. Use it  only when you are dealing with an array containing numbers in a given range (like 1 to N, or 0 to N). The core idea is that in a sorted array, the number  5 should ideally be at index  4. You iterate through the array and continuously swap numbers into their "correct" indices.
  • Real MNC Problems it Solves:
  • Database Integrity: Finding missing or duplicate user IDs in a sequential database column in strictly O(N)time and O(1) space.

The Java Skeleton:

public void cyclicSortTemplate(int[] nums) {

int i = 0;

while (i < nums.length) {

// The index where this number *should* belong

// (Assuming numbers are 1 to N. If 0 to N, it's just 'nums[i]')

int correctIndex = nums[i] - 1;

// If the number is within our valid range AND not currently at its correct index

if (nums[i] > 0 && nums[i] <= nums.length && nums[i] != nums[correctIndex]) {

// Swap them

int temp = nums[i];

nums[i] = nums[correctIndex];

nums[correctIndex] = temp;

} else {

// Only move to the next index if the current number is correct (or out of bounds)

i++;

}

}

// After this loop, the array is sorted. You can run a second loop to find the missing/duplicate element.

}

Common Variations (with details):

1. Find the Missing Number: Given an array from 0 to N with one missing number. Run the cyclic sort, then iterate through; the index that does not match its number is your missing number.

2. Find All Duplicates in an Array: The array has numbers from 1 to N, but some appear twice. Sort it cyclically. Any number sitting in the wrong index at the end is a duplicate.

3. First Missing Positive (Hard): You are given an unsorted array that includes negative numbers and zeroes. You must find the smallest missing positive integer. (You use cyclic sort to put all positive numbers in their correct places, ignoring negatives, then find the first gap).

6. In-place Reversal of a LinkedList

  • What it does: Reverses the connections between nodes in a Linked List strictly without using extra memory (you cannot put the values in an array and read them backwards). It relies on manipulating three pointers simultaneously:  previous,  current, and  next.
  • Real MNC Problems it Solves:
  • State Rollbacks: Reversing a sequence of actions or state changes in systems where memory allocation is highly restricted (like embedded systems or low-level OS tasks).

The Java Skeleton:

class ListNode {

int val;

ListNode next;

}

public ListNode reverseLinkedListTemplate(ListNode head) {

ListNode previous = null;

ListNode current = head;

ListNode next = null;

while (current != null) {

// 1. Temporarily store the next node

next = [current.next](http://current.next);

// 2. Reverse the current node's pointer to point backwards

[current.next](http://current.next) = previous;

// 3. Move 'previous' and 'current' one step forward for the next loop

previous = current;

current = next;

}

// 'previous' will be pointing to the new head of the reversed list

return previous;

}

Common Variations (with details):

1. Reverse a Sub-list: Instead of reversing the whole list, you are given a start position P and an end position Q. You must navigate to P, reverse only the nodes up to Q, and reconnect the reversed segment to the rest of the list.

2. Reverse Nodes in k-Group (Hard): A classic Amazon/Microsoft question. You reverse the first k nodes, then the next k nodes, and so on. If the final group is less than k, you leave it as is.

3. Palindrome LinkedList: You must check if a LinkedList reads the same forwards and backwards in O(1) memory. (Solution: Use Fast/Slow pointers to find the middle, reverse the second half of the list, compare the two halves, and then reverse it back to restore the original list).

7. Breadth-First Search (BFS)

  • What it does: Explores a tree or graph level by level. It visits the root node, then all of the root's immediate children, then all of the grandchildren, moving horizontally before moving vertically. It relies heavily on a Java  Queue (FIFO - First In, First Out).
  • Use case: Use this whenever a problem asks for the  "shortest path," "minimum steps," or a "level-order" traversal.
  • Real MNC Problems it Solves:
  • Social Networks (LinkedIn/Facebook): Finding the shortest degree of connection between two users (e.g., "2nd-degree connection").
  • Web Crawling: A search engine crawler indexing the immediate links on a homepage before diving deeper into subpages.

The Java Skeleton (Tree Level-Order Traversal):

import java.util.*;

class TreeNode {

int val;

TreeNode left, right;

}

public List<List<Integer>> bfsTemplate(TreeNode root) {

List<List<Integer>> result = new ArrayList<>();

if (root == null) return result;

Queue<TreeNode> queue = new LinkedList<>();

queue.offer(root); // Start with the root

while (!queue.isEmpty()) {

int levelSize = queue.size();

List<Integer> currentLevel = new ArrayList<>();

// Process all nodes exactly at the current level

for (int i = 0; i < levelSize; i++) {

TreeNode currentNode = queue.poll();

currentLevel.add(currentNode.val);

// Add the children to the queue for the NEXT level

if (currentNode.left != null) queue.offer(currentNode.left);

if (currentNode.right != null) queue.offer(currentNode.right);

}

result.add(currentLevel);

}

return result;

}

Common Variations:

1. Binary Tree Zigzag Level Order Traversal: Instead of reading left-to-right every time, you alternate (Left-to-Right, then Right-to-Left) by reversing the  currentLevel list before adding it to the result.

2. Minimum Depth of a Binary Tree: The moment you pull a node from the queue that has no left or right child, you immediately return the current level depth. That is your shortest path to a leaf.

3. Word Ladder (Graph BFS): Finding the shortest transformation sequence from a start word to an end word, changing one letter at a time (each word is a node, each 1-letter difference is an edge).

8. Depth-First Search (DFS)

  • What it does: Plunges as deeply as possible down a single branch before backtracking. Instead of moving horizontally, it goes vertically down to a leaf node, processes it, and then retreats. It relies on a Java  Stack (LIFO - Last In, First Out) or, more commonly and cleanly, the system's  Call Stack via Recursion.
  • Use case: Use this when a problem asks you to search through  all possible paths, check if a path exists from A to B, or when dealing with permutations/combinations.
  • Real MNC Problems it Solves:
  • File System Search: When you search for a file on your Mac or Windows machine, the OS uses DFS to dive deep into a specific folder and its subfolders before moving on to the next main folder.
  • Game AI (Chess/Checkers): Simulating a specific sequence of moves all the way to a win/loss state before evaluating a different sequence of moves.

The Java Skeleton (Recursive Tree Traversal):

public boolean dfsTemplate(TreeNode root, int targetSum) {

// 1. Base Case: If we hit a null node, this path doesn't work

if (root == null) {

return false;

}

// 2. Check if we've reached our goal (e.g., a leaf node with the exact remaining sum)

if (root.left == null && root.right == null && root.val == targetSum) {

return true;

}

// 3. Recursive Step: Dive down the left and right branches, updating the target

boolean leftPath = dfsTemplate(root.left, targetSum - root.val);

boolean rightPath = dfsTemplate(root.right, targetSum - root.val);

// If either path works, return true

return leftPath || rightPath;

}

Common Variations:

1. Path Sum II: Instead of just returning  true or  false, you pass a  List<Integer> down the recursive calls to keep track of the exact nodes in the valid path.

2. Lowest Common Ancestor: Finding the deepest shared parent of two nodes in a tree. (If you recursively search and find Node A in the left subtree and Node B in the right subtree, the current node is the ancestor).

3. Number of Islands (Graph DFS/Matrix): Given a 2D grid of 1s (land) and 0s (water), you iterate through the matrix. When you find a 1, you trigger a DFS to "sink" (turn to 0) all connected 1s, counting that as one total island.

9. Topological Sort (Directed Acyclic Graphs)

  • What it does: It provides a linear ordering of vertices in a directed graph where dependencies exist. If Node A points to Node B (A→B), Node A must appear before Node B in the final array. It works by tracking the "In-degree" (how many incoming edges a node has).
  • Use case: Use this strictly when dealing with  dependencies, prerequisites, or scheduling tasks that must be done in a specific order.
  • Real MNC Problems it Solves:
  • Package Managers (NPM/Yarn): When you run  npm install in your MERN backend, NPM uses Topological Sort to ensure that base libraries are installed before the frameworks that depend on them.
  • CI/CD Pipelines: Determining the order in which microservices should be built and deployed to AWS.

The Java Skeleton (Kahn's Algorithm):

import java.util.*;

public List<Integer> topologicalSortTemplate(int vertices, int[][] edges) {

List<Integer> sortedOrder = new ArrayList<>();

if (vertices <= 0) return sortedOrder;

// 1. Initialize the Graph and In-Degree array

HashMap<Integer, Integer> inDegree = new HashMap<>();

HashMap<Integer, List<Integer>> graph = new HashMap<>();

for (int i = 0; i < vertices; i++) {

inDegree.put(i, 0);

graph.put(i, new ArrayList<>());

}

// 2. Build the Graph

for (int[] edge : edges) {

int parent = edge[0], child = edge[1];

graph.get(parent).add(child);

inDegree.put(child, inDegree.get(child) + 1); // Child has one more prerequisite

}

// 3. Find all sources (nodes with 0 prerequisites)

Queue<Integer> sources = new LinkedList<>();

for (Map.Entry<Integer, Integer> entry : inDegree.entrySet()) {

if (entry.getValue() == 0) sources.offer(entry.getKey());

}

// 4. Process the sources

while (!sources.isEmpty()) {

int vertex = sources.poll();

sortedOrder.add(vertex);

// Get the node's children to decrement their in-degrees

for (int child : graph.get(vertex)) {

inDegree.put(child, inDegree.get(child) - 1);

// If in-degree becomes 0, it's a new source!

if (inDegree.get(child) == 0) {

sources.offer(child);

}

}

}

// 5. Check for Cycles (If we couldn't process all vertices, there's a circular dependency)

if (sortedOrder.size() != vertices) {

return new ArrayList<>(); // Graph has a cycle, scheduling is impossible

}

return sortedOrder;

}

Common Variations:

1. Course Schedule: You are given a list of courses and their prerequisites. You just need to return  true or  false to determine if it is possible to finish all courses (checking for cycles).

2. Alien Dictionary (Hard): You are given a list of words from a made-up language sorted lexicographically. You must use Topological Sort to figure out the alphabetical order of the letters in that specific language. (This is a frequent question at Meta/Facebook).

10. Top 'K' Elements

  • What it does: It uses Java's  PriorityQueue (a Heap data structure) to keep track of the largest, smallest, or most frequent elements in a dataset without sorting the entire array. If you need the top K  largest elements, you use a Min-Heap of size K. If you need the K  smallest, you use a Max-Heap.
  • Use case: The moment you see the words  "top," "largest," "smallest," "Kth," or  "most frequent" in a problem description, you immediately reach for a Heap.
  • Real MNC Problems it Solves:
  • Social Media (Twitter/X): Calculating the "Top 10 Trending Hashtags" in real-time from millions of tweets without sorting the entire database.
  • E-Commerce (Amazon): Displaying the "Top 5 recommended products" based on user similarity scores.

The Java Skeleton (Finding K Largest Elements):

import java.util.*;

public List<Integer> topKElementsTemplate(int[] nums, int k) {

// 1. Initialize a Min-Heap (default PriorityQueue in Java)

PriorityQueue<Integer> minHeap = new PriorityQueue<>();

for (int i = 0; i < nums.length; i++) {

// 2. Add the element to the heap

minHeap.add(nums[i]);

// 3. If heap size exceeds K, remove the smallest element.

// This ensures the heap ONLY holds the K largest elements we've seen so far.

if (minHeap.size() > k) {

minHeap.poll();

}

}

// 4. Return the contents of the heap

return new ArrayList<>(minHeap);

}

Common Variations:

1. Kth Largest Element in an Array: (Exactly the template above, just return  minHeap.peek() at the end).

2. Top K Frequent Elements: (First, count frequencies using a  HashMap. Then, put the map keys into the Heap, using a custom comparator to sort by their frequency value instead of the number itself).

3. Sort Characters By Frequency: (Similar to above, but applied to a String).

11. Two Heaps

  • What it does: It uses two Priority Queues simultaneously: a Max-Heap to store the smaller half of the numbers, and a Min-Heap to store the larger half. By keeping both heaps perfectly balanced in size, the "middle" elements are always instantly accessible at the top of the heaps.
  • Use case: Use this strictly when you need to find the  median of a continuously growing stream of numbers.
  • Real MNC Problems it Solves:
  • Fintech/Trading: Calculating the rolling median price of a stock ticker as thousands of transactions happen per second.
  • System Metrics: Finding the median server response time to filter out extreme outliers (like a server taking 10 seconds to respond).

The Java Skeleton (Median of a Number Stream):

import java.util.*;

class MedianFinder {

PriorityQueue<Integer> maxHeap; // Lower half of numbers

PriorityQueue<Integer> minHeap; // Upper half of numbers

public MedianFinder() {

maxHeap = new PriorityQueue<>(Collections.reverseOrder());

minHeap = new PriorityQueue<>();

}

public void insertNum(int num) {

// 1. Add to maxHeap first

maxHeap.add(num);

// 2. Balance: Ensure every number in maxHeap is smaller than minHeap

minHeap.add(maxHeap.poll());

// 3. Maintain size: maxHeap can have at most 1 more element than minHeap

if (maxHeap.size() < minHeap.size()) {

maxHeap.add(minHeap.poll());

}

}

public double findMedian() {

if (maxHeap.size() == minHeap.size()) {

return (maxHeap.peek() + minHeap.peek()) / 2.0; // Even number of elements

}

return maxHeap.peek(); // Odd number of elements (maxHeap has the extra one)

}

}

Common Variations:

1. Find Median from Data Stream: (The classic template above).

2. Sliding Window Median (Hard): (Combines the Sliding Window pattern with Two Heaps to find the median of every contiguous subarray of size K).

3. Maximize Capital (Hard): (A greedy algorithm where you use a Min-Heap to track projects you can afford, and a Max-Heap to track the profit of those projects).

12. K-way Merge

  • What it does: Whenever you have multiple sorted arrays or linked lists and need to merge them into one, you put the  first element of each list into a Min-Heap. You pop the smallest element, add it to your final result, and then push the  next element from that specific list back into the Heap.
  • Use case: Use this when a problem asks you to merge  K sorted arrays or  K sorted Linked Lists.
  • Real MNC Problems it Solves:
  • Distributed Databases: If a database is split across 5 different geographic servers (sharding) and you run a query, the central system uses K-way merge to combine the 5 sorted results into one master list for the user.

The Java Skeleton (Merging K Sorted Linked Lists):

import java.util.*;

class ListNode {

int val;

ListNode next;

}

public ListNode mergeKListsTemplate(ListNode[] lists) {

if (lists == null || lists.length == 0) return null;

// 1. Min-Heap comparing ListNode values

PriorityQueue<ListNode> minHeap = new PriorityQueue<>((a, b) -> a.val - b.val);

// 2. Add the root (first element) of each list to the Heap

for (ListNode node : lists) {

if (node != null) {

minHeap.add(node);

}

}

ListNode dummy = new ListNode(0);

ListNode current = dummy;

// 3. Extract smallest, and push the next element from that list

while (!minHeap.isEmpty()) {

ListNode smallest = minHeap.poll();

[current.next](http://current.next) = smallest;

current = [current.next](http://current.next);

if ([smallest.next](http://smallest.next) != null) {

minHeap.add([smallest.next](http://smallest.next));

}

}

return [dummy.next](http://dummy.next);

}

Common Variations:

1. Merge K Sorted Lists: (The classic template).

2. Kth Smallest Number in M Sorted Lists: (Instead of merging everything, you just run the  while loop K times and return the Kth popped element).

3. Kth Smallest Element in a Sorted Matrix: (Treat each row of the 2D matrix as an individual sorted list and apply the pattern).

13. Modified Binary Search

  • What it does: Standard binary search only works on perfectly sorted arrays. Modified binary search adapts the O(logn) logic to work on arrays that are sorted but have been shifted, rotated, or are of infinite length.
  • Use case: Use this when you need to search an array in better than O(N) time, but the array has a "twist" (e.g.,  [4, 5, 6, 7, 0, 1, 2]).
  • Real MNC Problems it Solves:
  • Log Parsing: Searching for a specific timestamp in server logs that are rotated at midnight (meaning the chronological order suddenly resets back to zero in the middle of the file).

The Java Skeleton (Search in Rotated Sorted Array):

public int searchRotatedTemplate(int[] nums, int target) {

int left = 0, right = nums.length - 1;

while (left <= right) {

int mid = left + (right - left) / 2;

if (nums[mid] == target) return mid; // Found it

// Trick: Determine WHICH half is strictly sorted

if (nums[left] <= nums[mid]) {

// Left half is perfectly sorted

if (target >= nums[left] && target < nums[mid]) {

right = mid - 1; // Target is in the left half

} else {

left = mid + 1; // Target must be in the right half

}

} else {

// Right half is perfectly sorted

if (target > nums[mid] && target <= nums[right]) {

left = mid + 1; // Target is in the right half

} else {

right = mid - 1; // Target must be in the left half

}

}

}

return -1;

}

Common Variations:

1. Search in Rotated Array: (The template above).

2. Find Minimum in Rotated Sorted Array: (Instead of looking for a target, you look for the point where the array "drops" from high to low).

14. Backtracking (Subsets / Combinations)

  • What it does: It systematically explores all possible solutions by building a candidate solution step-by-step. If it realizes the current path cannot lead to a valid solution (or if it finishes a valid path), it "backtracks" by undoing its last choice and trying a different branch.
  • Use case: Use this whenever a problem asks you to generate  "all possible..." subsets, permutations, combinations, or to solve a maze/puzzle (like Sudoku).
  • Real MNC Problems it Solves:
  • Cybersecurity: Brute-forcing password combinations by generating all possible permutations of a character set.
  • Logistics & Routing: Calculating all possible delivery routes for a fleet of trucks before feeding the paths into an optimization engine.

The Java Skeleton (Generating All Subsets):

import java.util.*;

public List<List<Integer>> backtrackingTemplate(int[] nums) {

List<List<Integer>> result = new ArrayList<>();

// Arrays.sort(nums); // Optional: if the problem requires handling duplicates

backtrack(result, new ArrayList<>(), nums, 0);

return result;

}

private void backtrack(List<List<Integer>> result, List<Integer> tempList, int[] nums, int start) {

// 1. Add the current subset to our final result (Deep copy is required!)

result.add(new ArrayList<>(tempList));

// 2. Iterate through the remaining choices

for (int i = start; i < nums.length; i++) {

// 3. Make a choice (Include the number)

tempList.add(nums[i]);

// 4. Explore further down this path (increment 'start' so we don't reuse elements)

backtrack(result, tempList, nums, i + 1);

// 5. BACKTRACK: Undo the choice to explore a different path

tempList.remove(tempList.size() - 1);

}

}

Common Variations:

1. Permutations: (Instead of starting the  for loop at  start, you always start at  0 but keep a boolean  visited array so you don't reuse the same number in the current path).

2. Combination Sum: (You are given a target number. You keep adding elements and recurse. If the sum exceeds the target, you backtrack. If it equals the target, you save the  tempList).

3. N-Queens (Hard): (Placing queens on a chessboard such that none attack each other. You place a queen, validate the board, and if it's safe, recurse to the next row. If no safe spot exists, backtrack).

15. Dynamic Programming: 0/1 Knapsack

  • What it does: Dynamic Programming (DP) is essentially "smart recursion." It breaks a problem into smaller overlapping subproblems, solves them once, and stores the results in an array (Memoization or Tabulation) so it never calculates the same thing twice. The "0/1 Knapsack" is the foundation of DP optimization, where you must either take an item (1) or leave it (0) to maximize profit within a capacity.
  • Use case: Use this whenever a problem asks you to  "maximize/minimize" something, find the  "number of ways," or when you have limited capacity (like time or budget).
  • Real MNC Problems it Solves:
  • Cloud Computing: AWS allocating virtual machines to a physical server. The physical server has limited RAM (capacity), and AWS wants to pack in as many high-paying instances (profit) as possible.
  • Financial Portfolio: Selecting a combination of stocks to maximize expected return without exceeding your total investment budget.

The Java Skeleton (Bottom-Up 2D Tabulation):

public int knapsackTemplate(int[] profits, int[] weights, int capacity) {

int n = profits.length;

if (capacity <= 0 || n == 0 || weights.length != n) return 0;

// dp[i][c] represents the max profit for 'i' items with 'c' capacity

int[][] dp = new int[n][capacity + 1];

// 1. Base case: If we have only 1 item, we take it if it fits the capacity

for (int c = 0; c <= capacity; c++) {

if (weights[0] <= c) {

dp[0][c] = profits[0];

}

}

// 2. Process all other items and capacities

for (int i = 1; i < n; i++) {

for (int c = 1; c <= capacity; c++) {

int profitIfIncluded = 0;

int profitIfExcluded = 0;

// Choice A: Include the item (if it fits)

if (weights[i] <= c) {

// Profit of current item + max profit of remaining capacity from previous items

profitIfIncluded = profits[i] + dp[i - 1][c - weights[i]];

}

// Choice B: Exclude the item

// Max profit is just whatever we could get from the previous items at this capacity

profitIfExcluded = dp[i - 1][c];

// 3. Take the maximum of both choices

dp[i][c] = Math.max(profitIfIncluded, profitIfExcluded);

}

}

// The bottom-right cell contains the maximum profit for all items at full capacity

return dp[n - 1][capacity];

}

Common Variations:

1. Subset Sum (Boolean DP): (Instead of maximizing profit, the DP array stores  true/false to determine if a subset of numbers can add up to a specific target).

2. Equal Subset Sum Partition: (Can you split an array into two halves with equal sums? Just calculate the total sum of the array, divide by 2, and use the Subset Sum logic to see if you can reach exactly that half-sum).

3. Target Sum: (Assigning  + or   to numbers in an array to reach a target. It mathematically converts directly into a 0/1 Knapsack problem).
